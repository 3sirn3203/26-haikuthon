# L0: 데이터 패키지 누수 감사 (`train_v1`, `test_v1`)

`scripts/check_leaks.py`, `scripts/pair_hn.py`로 측정했습니다. 원본 수치는 `audit.json`에 있습니다. 문항 원문과 id 목록은 싣지 않았습니다.

## 구조적 누수: 패키지를 그대로 배포하면 문제가 되는 것

| 항목 | train | test | 영향 |
|---|---|---|---|
| 원본 이미지 파일 id = 프롬프트 id | 100% | 100% | 프롬프트 id를 이미지 id로 그대로 쓰면 **만점** |
| HN의 id가 원본 뒤 범위에 몰려 있음 | 4000–4499 | 08000–14999(폴더도 분리) | id만 보고 HN을 후보에서 제외할 수 있음 |
| prompts.jsonl에 HN 행이 `"hard_negative"`로 표시됨 | 예 | 예 | 위와 같음 |
| HN 파일 순서 = 출처 원본 순서 (HN `N+k`는 원본 `k`의 변형) | 예 | 예 | HN과 원본을 짝지을 수 있음 |

- HN과 출처를 짝짓는 규칙은 픽셀로 검증했습니다. 32×32 흑백 썸네일 nearest-neighbor 기준으로, 규칙상 출처가 1등인 비율은 test 82%, train 50%입니다. 유사도 중앙값은 0.83이고 무작위 쌍은 0.04입니다.
  - 시드를 공유해서 원본과 HN의 구도가 비슷한 것으로 보입니다.
  - train의 1등 비율이 낮은 것은 train HN이 개수 변경처럼 구도가 크게 바뀌는 변형을 더 많이 포함하기 때문일 가능성이 있습니다(추정).
- 위 규칙으로 정하면 **Public(HN이 없는 문항) = test `7000–7999`**입니다. 이 중 stage1 '기준' 문항은 98개뿐이고 나머지는 묶음 문항입니다.

## 깨끗한 것

- PNG chunk는 모든 파일이 `IHDR, IDAT, IEND`뿐입니다. tEXt·eXIf 같은 메타데이터가 없습니다.
- 모든 파일이 768×768, 8bit RGB입니다.
- 원본과 HN 구분 AUC(0.5 = 신호 없음)

| 신호 | train | test |
|---|---|---|
| 파일 크기 | 0.53 | 0.50 |
| 평균 밝기 | 0.51 | 0.51 |
| 대비 | 0.50 | 0.50 |
| 따뜻함(R−B) | 0.54 | 0.53 |

  단순 통계로는 HN을 구분할 수 없습니다. 임베딩 기반 탐지기는 L2에서 따로 잽니다.
- train과 test 원본 구분 AUC는 파일 크기 0.53, 밝기 0.53, 대비 0.51입니다. 단순 통계로는 생성기 차이가 보이지 않습니다. stage3 설정대로 같은 생성기일 가능성이 높지만, 임베딩 기반 검사로 다시 확인합니다.

## 배포 전 권고

1. 이미지 id를 무작위 문자열로 바꾸고, 원본과 HN을 한 폴더에 섞습니다.
2. 참가자용 prompts에서 HN 행을 제거합니다.
3. 정답 매핑(프롬프트 id ↔ 이미지 id)은 채점 서버에만 둡니다.
4. 원본과 HN의 시드 공유는 출제 의도(시각적으로 매우 비슷한 HN)에는 맞습니다. 하지만 이미지끼리 비교해 쌍을 찾을 수 있게 되므로, 그 영향을 L4에서 따로 측정합니다.
