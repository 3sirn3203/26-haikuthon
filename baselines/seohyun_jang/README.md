## chan_lee와 다른 점
1. **CUDA 실측**: chan_lee 수치는 전부 Mac(MPS). 규정 기준(24GB CUDA)에 가까운 **NVIDIA L4**에서 캐시 없이 다시 잼.
2. **재정렬 평가 규모 3배**: 400문항 → **1183문항**(층화 부분집합 Private 1,400 + Public 200 중 30분 안에 끝난 문항).
3. **새 방법 2개 (B5)** — 같은 1183문항에서 비교
   - **M1 점수 융합**: VLM yes/no 점수 + w × (1단계 SigLIP2 점수 z-score). chan_lee는 재정렬 후보를 1단계보다 무조건 위에 올려 1단계 정보를 버림.
     w는 문항을 반으로 나눠 한쪽에서 고르고 다른 쪽에서 평가(2-fold, 두 fold 모두 w=1).
     → 재정렬만 K=10 **0.8022 → 융합 K=10 0.8409** (Private 0.7935 → 0.8343).
     K=5: 0.8123 → 0.8292. 추가 비용 0.
   - **M2 비교형(pairwise) 재정렬**: 상위 2장을 한 번에 보여 주고 "1/2 중 어느 쪽이 맞나"를 양쪽 순서로 물어 위치 편향 상쇄.
     M1 K=5 위에서 0.8292 → **0.8321** (작은 개선),
     문항당 0.51s 추가, peak 8.8GB.
4. **재현 확인**: B1 0.4263 (chan_lee MPS 0.4267), B2 0.6771 (chan_lee 0.6796) — 장비가 달라도 같은 값.

## 관찰
- 재정렬은 크게 이득(B2 1단계 대비 +0.13 수준), 하지만 VLM 단독 순위는 K가 커질수록 나빠짐(K5 > K10). **1단계 점수와 융합하면 K10이 가장 좋아짐** → VLM이 확신하고 틀리는 경우를 1단계가 보정.
- 비교형 재정렬은 위치 편향을 상쇄해도 이득이 작음. 상위 2장만 보는 구조라 R@1만 바뀌고, yes/no 단독 점수가 이미 대부분을 잡음.
- 시간: 재정렬이 지배적. 시간 제한을 정할 때 K와 VLM 크기가 핵심 손잡이.

## 시간 부족으로 못 한 다른 방법론 (아이디어와 근거)
- **슬롯 검증**: 템플릿 프롬프트를 객체·개수·속성·관계로 쪼개 슬롯별 질문 점수 합산.
- **재정렬 VLM LoRA 학습**: train 4,000쌍 + 묶음 negative로 yes/no 학습(현재 재정렬기는 zero-shot).
- **loophole 후보**: (1) HN은 원본과 같은 시드라 픽셀 쌍둥이 → 이미지 풀만으로 쌍 구조가 드러남. 어느 쪽이 원본인지 가리려면 결국 문항 간 정보가 필요해 L1(Hungarian)과 같은 계열이지만, 배포 전 **HN 시드 변경** 권고.
  (2) 생성기(Qwen-Image-2512 Lightning)와 시드 규칙이 알려지면 재생성 후 픽셀 일치로 정답 탐색 가능 → id 익명화·시드 비공개 필수.
- 쌍둥이 탐지 분석 결과: `analysis/` (e1_score_fusion.json, e2_twin_pairs.json)
