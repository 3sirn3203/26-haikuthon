## 핵심 결론

1. **재정렬 시간이 규정의 핵심 숫자** — 1단계 검색은 test 전체(8,000문항 × 15,000장)를 **약 6분**에 끝내지만,
   Qwen3.5-4B 재정렬은 **쌍당 0.153초**라서 test 전체를 K=5로 돌리면 **약 1.8시간(추정)** 걸린다.
2. **점수는 재정렬이 결정** — 파인튜닝 검색기 0.679 → VLM 재정렬 0.809 (+0.13, 같은 1,183문항).
   1단계 top-10 안에 정답이 98.8% 들어 있어서, 승부는 순서를 정하는 재정렬에서 난다.
3. **VLM 질문만 바꿔도 오른다** — "개수·색·재질·자세·좌우를 하나씩 확인하라"는 체크리스트형 질문: 0.811 → **0.828**.
   원래 질문 + 체크리스트 질문 + 1단계 점수를 합치면 **0.839** (튜닝 없이 동일 가중).
4. **원래 모델을 섞는 건 손해** — 파인튜닝 모델에 zero-shot 모델을 섞으면(WiSE-FT, 점수 앙상블) 0.677 → 0.58~0.65로 하락.
   이 과제는 파인튜닝으로 배운 "같은 장면, 다른 디테일" 구별 능력이 핵심.
5. **규정 허점: HN 시드** — HN이 원본과 같은 시드로 생성돼, **이미지만 보고 HN–원본 쌍의 78%를 정밀도 98%로 찾을 수 있다**.
   쌍이 없는 이미지에는 Public 정답의 94%가 들어 있다. → **배포 전 HN 시드 변경 권고**.

| 방법 | score | Public | Private |
|---|---|---|---|
| 원래 질문 (yes/no) | 0.8110 | 0.8534 | 0.8050 |
| 체크리스트형 질문 | 0.8276 | 0.8700 | 0.8216 |
| 원래 + 체크리스트 | 0.8198 | 0.8622 | 0.8138 |
| 원래 + 1단계 | 0.8071 | 0.8630 | 0.7992 |
| **원래 + 체크리스트 + 1단계** | **0.8390** | 0.8793 | 0.8333 |

- 체크리스트 질문을 하나 더 쓰면 VLM 채점이 두 배 → 쌍당 0.149s 추가.

> **융합 결과가 두 표에서 다른 이유** — B5는 VLM 점수는 그대로 두고 1단계 점수만 z-score로 바꿔 더했고(w는 문항을 반으로 나눠 고름),
> B7은 VLM 점수까지 후보 5장 안에서 z-score로 바꿔 동일 가중으로 더했다. 후보 5장만으로 표준화하면 VLM 점수 차이가 납작해져서
> 1단계 비중이 커지고, 문항도 1,183 vs 727로 다르다. **1단계 점수 융합은 합치는 방식에 민감**하므로, 쓸 거라면 val로 가중치를 골라야 한다.

## 규정 허점 분석 (loophole, 측정만 함)

이미지 15,000장을 32×32 흑백 썸네일로 줄여 서로 가장 닮은 이미지끼리 짝지음 (상호 최근접, 유사도 > 0.5). `analysis/e2_twin_pairs.json`

| 지표 | 값 |
|---|---|
| 찾은 쌍 / 실제 HN–원본 쌍 | 5,595 / 7,000 |
| 정밀도 | **97.7%** |
| 재현율 | **78.1%** |
| 쌍이 없는 이미지 중 Public 정답 비율 | 24.6% |
| Public 정답 1,000장 중 "쌍 없음"으로 분류된 비율 | **93.6%** |

- 원인: HN을 원본과 **같은 시드**로 생성해서 구도가 거의 같음.
- 의미: 이미지 풀만 보고도 "어떤 이미지가 HN 쌍의 일부인지"가 드러남. 쌍 중 어느 쪽이 원본인지 가리려면 결국 다른 문항 정보가 필요해서
  이찬님이 잰 문항 간 1:1 할당(L1, +0.10)과 같은 계열이지만, 현재 규정 문구("문항 간 정보 금지")로 막히는지는 애매함.
- **권고**: 배포 전 HN을 다른 시드로 다시 생성하거나, 규정에 "이미지 풀 구조 활용 금지"를 명시.
- 추가 위험: 생성 모델(Qwen-Image-2512 + Lightning)과 시드 규칙(`base_seed + sha256("<split>:<id>")`)이 알려지면
  프롬프트로 이미지를 재생성해 픽셀 일치로 정답을 찾을 수 있음 → id 익명화와 시드 비공개 필수.
